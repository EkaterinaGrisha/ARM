# Сравнение мультимодальных моделей на задачах чтения конструкторской документации

02.11.2026. Исходные данные: `eval/results/vlm-bench.md`, `eval/results/vlm-title-block.md`.

## 1. Цель и модели

Цель — сравнить локальные мультимодальные модели и классическое OCR при чтении растровых документов и сканов. Сравнение проводилось на двух объектах: основной надписи и технических требованиях (ТТ).

Модели отбирались по трём критериям:
- **локальный запуск** — документы заказчика не передаются внешним сервисам;
- **открытая лицензия**;
- **размер**, позволяющий запуск без серверного GPU.

Рассматривались два класса моделей:
- общие мультимодальные языковые модели (VLM) — модели общего назначения, которые отвечают на вопрос по изображению;
- документные OCR-модели — модели, обученные переводить изображение документа в текст.

## 2. Методика

Каждая модель запускалась отдельно на локальном сервере. Генерация была детерминированной: температура 0, фиксированное зерно. Все модели получали одни и те же изображения. Веса квантованы: у Qwen и Gemma до 4 бит, у Qianfan-OCR до 8 бит.

Режимы ответа:
- **Общие VLM** заполняют поля по заданной схеме (JSON).
- **OCR-модели и Tesseract** возвращают сплошной текст, и нужное значение ищется в нём.
- **Qianfan-OCR** измерена в обоих режимах.

Перед сравнением значения нормализуются: приводится регистр, «ё» заменяется на «е», выравниваются десятичный разделитель, пробелы, тире и кавычки, латинские буквы, совпадающие по начертанию с кириллическими, заменяются кириллическими.

### Задачи

1. **Основная надпись с целого листа.**
   - Данные: 17 листов реальной КД из открытых источников — альбом чертежей электровоза ВЛ60 (1963), станок ИЖ-250, альбомы приборов. Это сканы и фотографии. Бланки в основном не соответствуют ГОСТ 2.104, часть надписей выполнена от руки.
   - Подача: лист целиком, длинная сторона — 2000 пикселей.
   - Ответ: шесть полей — обозначение, наименование, материал, масса, масштаб, литера.
   - Из 102 полей (17 × 6) на листах заполнены 50, а 52 отсутствуют.
2. **Технические требования.**
   - Данные: 30 блоков ТТ синтетических растров и сканов, то есть сгенерированных чертежей с известной разметкой.
   - Подача: блок вырезается по эталонной разметке, поэтому измеряется только распознавание, без поиска области на листе.
   - Оценка: распознанный текст разбирается парсером ядра проекта. Сравнивается 61 параметр четырёх категорий: общие допуски, термообработка, твёрдость, покрытие.
3. **Ячейки основной надписи.** 112 ячеек основной надписи 20 синтетических документов, вырезанных по эталонной разметке.
4. **Конвейер проекта с моделью.**
   - Данные: 130 синтетических сканов.
   - Порядок: основную надпись читает OCR, модель дочитывает ячейки, которые OCR оставил пустыми.

### Метрики

- **Поля прочитаны верно** — значение в нужном поле совпадает с эталоном. Метрика определена только для ответа по схеме.
- **Верное значение есть в ответе** — эталонное значение целиком содержится в тексте ответа. Для текстовых ответов это единственная применимая мера. Она завышает результат: значение ещё нужно отнести к своему полю.
- **Заполнены отсутствующие поля** — модель вернула значение поля, которого на листе нет, то есть выдумала его.
- **Параметры распознаны** — параметр найден с верной категорией и наименованием.
- **Числовые диапазоны верны** — у параметра с числовыми границами, например «40…45 HRC», верны обе границы.
- **Ячейки прочитаны верно** — значение ячейки полностью совпадает с эталоном.
- **CER** (доля ошибочных символов) — число посимвольных правок, делённое на длину большей из двух строк. Усредняется по ячейкам.
- **Доля верных полей** (задача 4) — верно прочитанные поля среди полей, присутствующих в эталоне.
- **Время** — на одной и той же конфигурации оборудования. Оно служит только для сравнения моделей между собой.

## 4. Обсуждение

1. **Чтение основной надписи с целого листа требует понимания компоновки листа.** На реальных листах поля расположены нестандартно, часть надписей рукописная. Выделить поля смогли только модели с 27 млрд параметров. Малые VLM и OCR-модели распознают текст, но не относят его к полям. Qianfan-OCR в текстовом режиме, по просмотру её ответов, выдаёт текст лишь части листа (таблицу или ТТ) и до основной надписи часто не доходит.
2. **Qwen3.8-27B уступает Qwen3.6-27B на целом листе (28 полей против 40), хотя на вырезках результаты равны.** Отставание наблюдается почти по всем полям. Предположительная причина — иная предобработка изображения в использованной сборке (формат MLX против GGUF у Qwen3.6-27B): при уменьшении большого изображения теряется мелкий текст. Гипотеза не проверена.
3. **На вырезках все модели значительно превосходят Tesseract.** ТТ насыщены специальными знаками (±, Ø, HRC, «…»), а сканы зашумлены. Языковая модель восстанавливает знаки по контексту.
4. **У Qianfan-OCR в текстовом режиме при меньшем числе точных совпадений ячеек (71 против 90) ниже CER.** В её ответах кириллица частично заменена совпадающими по начертанию латинскими и греческими буквами, например «Δ» вместо «Д». Латинские замены устраняются нормализацией, греческие — нет. Поэтому ответ близок к эталону посимвольно, но не совпадает целиком.
5. **PaddleOCR-VL на целом листе не измерена из-за ошибок сервера**: сервер не обрабатывает служебные токены координат в её ответах. Причина низкой доли верных диапазонов (12 из 30) не исследована.
6. **Gemma 4 E4B чаще остальных заполняет отсутствующие поля** (10 из 52).
7. **Результаты задач 2 и 3 — верхняя оценка.** Область задана разметкой, а синтетические сканы чище реальных. Полный результат по ТТ недостижим ни для одной модели: часть формулировок не покрыта парсером.
8. **В конвейере прирост ограничен** тем, что модель дочитывает только пустые ячейки и не исправляет ячейки, неверно заполненные OCR. Наименование верно в 74 сканах из 130 во всех трёх конфигурациях.

## 5. Выводы

1. Для чтения основной надписи с целого листа пригодна только Qwen3.6-27B: 40 полей из 50 при 4 ложных значениях. Это примерно в 3 раза больше, чем верных значений в тексте Tesseract (13).
2. Для вырезанных областей (ТТ, ячейки) Qwen3.8-27B даёт ту же точность, что Qwen3.6-27B, и работает в 1,6 раза быстрее.
3. Среди малых моделей лучший результат на вырезках у Qianfan-OCR: 45 параметров ТТ из 61 и 90 ячеек из 112.
4. Подключение модели к конвейеру повышает долю верных полей с 0,650 до 0,743–0,747.

## 6. Дальнейшая работа

Планируется:

1. Измерить остальные модели (таблица 6) по той же методике.
2. Проверить гипотезу о потере разрешения у Qwen3.8-27B: подать лист фрагментами и в большем разрешении.
3. Распределить роли моделей по результатам:
   - чтение полей с целого листа;
   - распознавание вырезанных областей (ТТ, ячейки);
   - быстрое сплошное OCR.
4. Зафиксировать архитектурное решение: модель становится основным способом чтения растровых документов и сканов, а не только дочитывает за OCR.
