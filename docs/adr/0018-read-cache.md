# ADR-0018. Кэш ответов OCR и модели — по содержимому запроса, в локальной папке, включается явно

Статус: Принято 2026-11-11, предложено 2026-11-07 · Этап плана: 6

## Вопрос

Как повторный прогон получает те же прочтения OCR и мультимодальной модели без повторного чтения? Что входит в ключ, где лежит кэш, включён ли он по умолчанию и как он ведёт себя при параллельных заданиях API? Решение — первый пункт шага 3 [порядка работ](../PLAN.md#порядок-работ-до-демо): без кэша модель не может стать основным способом чтения растров.

## Контекст и ограничения

- Кейс: критерий «Работоспособность — воспроизводимость запуска» (CASE.md, критерии оценки, 4).
- Правила: воспроизводимость, в отчёте — имена и версии моделей; данные заказчика не попадают в git (`data/`, `models/`, `out/` игнорируются) и не уходят во внешние сервисы ([CONTRIBUTING.md](../../CONTRIBUTING.md#engineering-rules)).
- Факт: прогон конвейера на 130 синтетических сканах тратит на OCR 284 с. С моделью и проверкой всех ячеек он занимает от 1536 с с Qwen3.6-35B-A3B до 4987 с с Gemma 4 31B ([vlm-title-block.md](../../eval/results/vlm-title-block.md)). Каждый из 7 прогонов этого замера заново читает OCR те же сканы.
- Факт: крупная модель читает целиком 332 листа `arm-2` около 6 часов ([сводка 02.11.2026](../reports/2026-11-02-status.md)). При настройке правил на `arm-1` и `arm-2` ядро прогоняется по ним много раз, а изображения ячеек меняются редко.
- Факт: ответ Tesseract зависит только от пикселей, языков, режима `--psm`, списка допустимых символов и версии Tesseract (`kdcheck.ocr.tesseract.words`). Ответ модели зависит от пикселей, модели, промпта, зерна и ограничений запроса (`kdcheck.vlm.client.VlmClient.read`).
- Факт: задания API — отдельные процессы `kdcheck run` ([ADR-0006](0006-job-execution.md)), `workers` в `configs/api.yaml` позволяет запускать несколько сразу.
- Ограничение: ADR-0006 убрал SQLite и Redis из поставки.

Сценарии:

1. Повторный прогон с той же моделью → ни одного обращения к серверу модели, значения в отчёте те же.
2. Изменился код, который вырезает ячейку → другие пиксели → промах кэша, ячейка читается заново.
3. Новая версия промпта или Tesseract → промах.
4. Два задания одновременно пишут одну запись → файл записи цел, содержимое одно.
5. Комплект заказчика в API → по умолчанию ничего не остаётся на диске после задания.

## Варианты

- **A. Без кэша**, как сейчас.
- **B. Кэш стадий** ([ARCHITECTURE.md](../ARCHITECTURE.md#пайплайн), «каждая стадия пишет артефакты в рабочую папку»): повторно используются результаты стадии по документу целиком.
- **C. Кэш вызовов в папке**: запись на каждый вызов Tesseract и модели. Ключ — SHA-256 от всего, что определяет ответ: движок, версия, параметры запроса, промпт, хэш пикселей. Одна запись — один JSON-файл. Запись атомарная: временный файл, затем `os.replace`.
- **D. Кэш вызовов в SQLite**: те же ключи в одном файле базы.

| Критерий | A. Без кэша | B. Кэш стадий | C. Вызовы, папка | D. Вызовы, SQLite |
| --- | --- | --- | --- | --- |
| Сценарий 1 | нет | да | да | да |
| Сценарий 2: правка кода | — | промах всех документов: ключ — версия кода | промах только изменённых ячеек | как C |
| Сценарий 4: параллельные задания | — | рабочие папки раздельны | да: одинаковое содержимое, атомарная замена | да: блокировки базы |
| Новые компоненты поставки | нет | нет | нет | SQLite, против ADR-0006 |
| Отчёт и контракт | без изменений | без изменений | без изменений | без изменений |
| Цена отката | — | средняя | низкая: флаг и один модуль | низкая |

## Решение

Рекомендуем C.

- **Где.** Модуль `kdcheck.cache`: `lookup(engine, parts, compute)` возвращает сохранённый ответ или вызывает `compute` и сохраняет его ответ. Ошибки и тайм-ауты не сохраняются. Вызывают его `tesseract.words` (сохраняется сырой ответ `image_to_data`, порог уверенности и перевод в координаты страницы применяются после) и `VlmClient.read` (сохраняется текст ответа).
- **Ключ.** SHA-256 от JSON с движком, его версией и параметрами: для Tesseract — языки, `--psm`, допустимые символы, версия; для модели — тело запроса, где изображение заменено хэшем пикселей. Хэш пикселей — SHA-256 от режима, размера и байтов изображения, так что формат сжатия на ключ не влияет. Адрес сервера в ключ не входит, имя модели входит.
- **Хранение.** `<папка>/<движок>/<два знака ключа>/<ключ>.json`. В записи — ответ и параметры ключа без изображения. Изображения в кэш не попадают.
- **Включение.** По умолчанию кэш выключен. Включают его `kdcheck run --cache DIR` и `ARM_CACHE_DIR`. Замеры `eval/vlm_title_block.py` и `eval/synth_kits.py` включают его флагом `--cache`, в папке `data/cache` вне git. Без флага они читают заново, и время в результатах остаётся временем чтения. У API кэш включается `cache_dir` в `configs/api.yaml`, по умолчанию пусто: тексты документов заказчика не остаются на диске без решения заказчика.
- **Отчёт.** Значение из кэша несёт тот же `Evidence`: движок, его версию, способ и уверенность первого прочтения. Хэш настроек и контракт не меняются. Число попаданий и промахов пишется в журнал прогона.

## Последствия

- Код: `kdcheck.cache`, вызовы из `kdcheck.ocr.tesseract` и `kdcheck.vlm.client`, флаг `--cache` и `ARM_CACHE_DIR` в CLI, `cache_dir` в `configs/api.yaml` и в запуске задания. Замеры `eval/vlm_title_block.py` и `eval/synth_kits.py` получают флаг `--cache`.
- Тесты: второй прогон не вызывает Tesseract и сервер модели, а отчёт совпадает с первым; изменение пикселей, языков, промпта или версии даёт промах; ошибка сервера не сохраняется; запись атомарна.
- Замер на корпусе `eval/vlm_title_block.py`, 130 синтетических сканов. OCR — 261 с с пустым кэшем и 84 с с заполненным: 2875 вызовов Tesseract из кэша, оставшееся время — растеризация и поиск областей. С Qwen3.6-35B-A3B и проверкой всех ячеек — 961 с, когда OCR уже в кэше, и 94 с повторно: 858 прочтений модели из кэша. Отчёты повторных прогонов совпали с первыми полностью. Кэш после обоих прогонов — 16 МБ.
- Документы: ARCHITECTURE.md — строка 18 «Решений» и кэш в описании стадий; PLAN.md — пункт кэша этапа 6.
- Принимаем риск: ответ модели, сохранённый при первом прогоне, повторяется, даже если сервер теперь ответил бы иначе. Для воспроизводимости это и нужно. Чтобы перечитать, папку кэша удаляют.
- Принимаем риск: кэш не ограничен по размеру. Запись Tesseract по ячейке — около 1 КБ, по листу — десятки килобайт.

## Когда пересмотреть

Если кэш понадобится нескольким машинам сразу или записей станет больше сотен тысяч, переходим к D или к общему хранилищу: ключи и записи переносятся без изменений. Если заказчик разрешит хранить прочтения своих документов, кэш в API включается настройкой.
