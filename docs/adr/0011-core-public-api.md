# ADR-0011. Публичный API ядра: schemas, run, render и report

Статус: Принято 2026-10-20 · Этап плана: 3 (шаг 4 плана миграции)

## Вопрос

Какие модули `kdcheck` вправе импортировать API и другие модули `backend`, чтобы import-linter в CI закрепил границу ядра из [ADR-0010](0010-repo-layout.md)?

## Контекст и ограничения

- Кейс: «Отчёт в двух формах — машиночитаемой для дальнейшей интеграции и человекочитаемой для работы технолога» (CASE.md, стр. 3). «Над каждым блоком могут работать разные команды» (стр. 2).
- Правила: вся логика в `kdcheck`, API и веб только вызывают ядро ([CONTRIBUTING.md](../../CONTRIBUTING.md#engineering-rules)).
- ADR-0010: `backend` импортирует только `kdcheck.schemas`, `kdcheck.run` и `kdcheck.render`. Модуля `kdcheck.run` пока нет.
- ADR-0006: задание — отдельный процесс `kdcheck run`. API читает состояние и отчёт из папки задания.
- Факт: API строит Excel и HTML на лету из `report.json` через `kdcheck.report` (`backend/arm_web/main.py:128-144`).
- Факт: внешний конвейер (`ARM_PIPELINE_CMD`) пишет только `report.json` (`backend/arm_web/pipeline/external.py`). Excel и HTML для него есть только благодаря выгрузке на лету.
- Факт: `/api/health` берёт наличие OCR из `kdcheck.ocr.tesseract` (`main.py:69`). Встроенный конвейер API берёт из `kdcheck.pipeline` (`pipeline/__init__.py:16`).
- Замер: Excel на демо-комплекте (22 документа) строится за 34 мс, а на отчёте в 15 раз больше (330 документов) — за 358 мс. HTML — за 1 и 2 мс.

Сценарии:

1. Технолог скачивает Excel по заданию внешнего конвейера: файл есть.
2. Разработчик API случайно импортирует `kdcheck.checks`: CI красный.
3. Изменили вид Excel: старые задания отдаются в новом виде без перезапуска.

## Варианты

- **A. Добавить `kdcheck.report` к публичным модулям.** Появится модуль `kdcheck.run`: запуск конвейера и сведения о движках. API по-прежнему строит Excel и HTML на лету.
- **B. Только готовые файлы.** `kdcheck run` пишет три формы в папку задания, API отдаёт файлы. Для внешнего конвейера нужна команда `kdcheck report report.json -o папка`. Для старых заданий нужен перезапуск.
- **C. Один фасад `kdcheck.api`.** Он реэкспортирует запуск, рендер, выгрузки и сведения о движках. `backend` импортирует только `kdcheck.api` и `kdcheck.schemas`.

| Критерий | A. + report | B. Только файлы | C. Фасад |
| --- | --- | --- | --- |
| Сценарий 1 | да | да, через новую команду | да |
| Сценарий 2 | да | да | да |
| Сценарий 3 | да | нет, нужен перезапуск | да |
| Публичных модулей | 4 | 3 | 2 |
| Изменения сейчас | `kdcheck.run`, контракт | `kdcheck.run`, команда `report`, раздача файлов, контракт | фасад, контракт |
| Цена отката | низкая | средняя | низкая |
| Риск | API строит выгрузку на запрос: 0,4 с на большом комплекте | файлы расходятся с кодом выгрузок | фасад разрастается в свалку |

## Решение

Принят вариант A. Выгрузка из готового `report.json` дешёвая и не трогает недоверенные файлы, поэтому её не нужно выносить в процесс задания. Вариант A покрывает внешние конвейеры и старые задания без новой команды. Модули остаются по смыслу, без фасада.

Публичный API ядра:

| Модуль | Что даёт |
| --- | --- |
| `kdcheck.schemas` | Контракт отчёта |
| `kdcheck.run` | Запуск встроенного конвейера, тип колбэка прогресса, наличие OCR |
| `kdcheck.render` | PNG листа для просмотра |
| `kdcheck.report` | Excel, HTML, запись трёх форм отчёта |

## Последствия

- Новый модуль `kdcheck.run`. `backend` переходит на него и больше не импортирует `kdcheck.pipeline` и `kdcheck.ocr`.
- import-linter 2.15 (BSD-2-Clause) в группе dev, три контракта в корневом `pyproject.toml`:
  1. `arm_web` не импортирует напрямую `kdcheck.ingest`, `ocr`, `extract`, `normalize`, `checks`, `params`, `pipeline`. Через публичные модули — можно.
  2. Блок 1 (`kdcheck.checks`) и Блок 2 (`kdcheck.params`) не импортируют друг друга.
  3. `kdcheck.schemas` не импортирует другие модули ядра: контракт остаётся листом графа.
- `uv run lint-imports` — в CI и в pre-commit.
- ADR-0010 и ARCHITECTURE.md («Структура репозитория») ссылаются на этот список.
- Шаг 5 (ADR-0006) не меняется: задание станет процессом `kdcheck run`, API будет строить Excel и HTML из его `report.json`.

## Когда пересмотреть

Если выгрузка станет тяжёлой: PDF-отчёт или больше 1 с на реальном комплекте. Если заказчику нужно хранить отчёт ровно в том виде, в каком его выдали. Тогда переходим на B вместе с процессом задания.
