# ADR-0014. Мультимодальная модель — через локальный сервер с OpenAI-совместимым API; первая задача — ячейки основной надписи сканов

Статус: Предложено · Дата: 2026-10-26 · Этап плана: 6

## Вопрос

Как ядро вызывает мультимодальную модель (VLM) с открытыми весами и где применяет её первой? Задача команды (7) от 26.10.2026: подключить к прототипу локально скачанную модель.

## Контекст и ограничения

- Кейс: подходы «OCR, VLM, LLM, правила или их сочетание — на усмотрение команды, с обоснованием выбора». «По каждому извлечённому значению видно, из какого документа и какой области страницы оно получено» (CASE.md, стр. 3).
- Кейс: критерий «Точность извлечения … в том числе на плохих сканах»; в передачу входят «модели и промпты» (стр. 4).
- Правила: модель добавляем только с измеренным выигрышем; промпты — версионные файлы в `prompts/`; имя и версия модели — в отчёте. Документы заказчика не уходят во внешние API без разрешения АРМ ([CONTRIBUTING.md](../../CONTRIBUTING.md#engineering-rules)).
- [ADR-0006](0006-job-execution.md): каждое задание — отдельный процесс `kdcheck run`, лимит памяти — 8192 МБ (`configs/api.yaml`). ARCHITECTURE.md уже предусматривает сервер моделей с OpenAI-совместимым API и интерфейс `VlmClient`.
- Контракт 1.3 уже содержит `method: vlm`, статус значения `conflict` и версии движков: схема не меняется.
- Факт: точность основной надписи на сканах демо-комплекта с OCR — 0,625 ([pdf-backends.md](../../eval/results/pdf-backends.md)). На обоих сканах Tesseract не нашёл материал.
- Проба 26.10.2026: Apple M5, 32 ГБ, LM Studio, Gemma 4 E4B Q4_K_M (Apache-2.0). Ячейка при 300 dpi читается за 1,6–2,1 с, если ответ ограничен JSON-схемой. Без схемы модель рассуждает: при лимите 64 токена 9 ячеек из 12 вернулись пустыми.
- Проба: модель верно прочла материал «Ст3сп ГОСТ 380-2005», пропущенный OCR. Обозначение пришло латиницей «APM.303411.203»; к кириллице его приводит существующая нормализация.
- Факт: Gemma 4 E4B загружается 8,9 с и занимает 5,9 ГиБ. Qwen3.6-27B Q4_K_M — 17,5 ГБ, больше лимита памяти задания. Колесо torch 2.14.1 для Python 3.11 — 127 МБ на macOS arm64, 555 МБ на Linux x86_64.

## Варианты

Как вызывать модель:

- **A. Сервер моделей.** Ядро отправляет вырезку и промпт в `/v1/chat/completions`, ответ ограничен JSON-схемой. Сервер — отдельный процесс: LM Studio, llama.cpp или Ollama на ноутбуке, vLLM на машине с GPU. Клиент написан на стандартной библиотеке Python.
- **B. Модель в процессе задания:** transformers и torch, llama-cpp-python или mlx-vlm.
- **C. Оставить как есть:** только Tesseract, улучшать шаблоны и предобработку.

| Критерий | A. Сервер | B. В процессе задания | C. Как есть |
| --- | --- | --- | --- |
| Процесс на задание, лимит 8 ГБ | модель загружена один раз | загрузка в каждом задании; 27B не помещается | не касается |
| Смена модели | строка в `models.yaml` | код под архитектуру модели | — |
| Зависимости ядра | новых нет | torch и transformers или нативные сборки | новых нет |
| Сбой модели | сервер недоступен — модель выключается, прогон идёт | нехватка памяти завершает задание | — |
| Данные заказчика | HTTP: нужен запрет адресов вне машины | не покидают процесс | не покидают процесс |
| Платформы | Mac и Linux с GPU одним кодом | разные сборки под Metal и CUDA | — |
| Точность на сканах | проба: материал найден | та же модель — та же точность | 0,625 на демо-сканах |
| Лицензии поставки | llama.cpp — MIT, vLLM — Apache-2.0; LM Studio — только для разработки | torch — BSD-3, transformers — Apache-2.0 | — |

Где применять первой:

- **Ячейки основной надписи по шаблону ГОСТ.** Модель читает текст одной ячейки, значение нормализуют и проверяют те же правила, что и для OCR. Bbox — ячейка шаблона, прослеживаемость сохраняется.
- **Лист целиком с ответом JSON.** Проще, но значение теряет bbox. По исследованиям, VLM без схемы извлекает основную надпись с F1 0,67 ([RESEARCH.md](../RESEARCH.md)).

## Решение

Рекомендуем A с ячейками основной надписи сканов:

- `kdcheck.vlm` — клиент OpenAI-совместимого сервера. Ответ ограничен схемой `{"text": …}`, температура 0, сид задан. Адрес вне этой машины — ошибка настроек без `allow_remote: true`, которое ставится только с разрешения АРМ.
- Модель читает ячейки скана, которые OCR не заполнил; с `verify: true` — и заполненные. Значение получает `method: vlm`, движок — имя модели, версия — промпт. Расхождение с OCR даёт статус `conflict`, второе прочтение уходит в примечание документа.
- Пока модель не откалибрована на эталоне (этап 6), каждое её значение помечается «проверить»: `vlm` входит в `review.methods`.
- По умолчанию выключено: `enabled: false`, включает `ARM_VLM=1`. Включаем по умолчанию, только если замер на эталоне покажет выигрыш.
- Промпт — `prompts/title_block_cell.v1.txt`. Изменённый промпт — новый файл с новой версией.

## Последствия

- Код: клиент `kdcheck.vlm`; правила значения ячейки в `kdcheck.extract.title_block` общие для OCR и модели; шаг конвейера после разбора основной надписи скана; модель с версией промпта в `KitInfo.engines`.
- Настройки: раздел `vlm` в `models.yaml`, `confidence.vlm` и `vlm` в `review.methods` в `ingest.yaml`; хэш настроек их учитывает. Каталог `prompts/` — в репозитории и в Docker-образе.
- Тесты: клиент против локальной заглушки сервера, запрет внешнего адреса, заполнение пустой ячейки, конфликт с OCR, недоступный сервер не останавливает прогон.
- Замер `eval/vlm_title_block.py`: основная надпись сканов с моделью и без на демо-комплекте и синтетических комплектах; результат — `eval/results/vlm-title-block.md`.
- Документы: ARCHITECTURE.md — модели по стадиям и строка 14 в «Решениях»; README; PLAN.md, этап 6.
- Профиль GPU с vLLM в `docker compose` — на этапе 9, как записано в ARCHITECTURE.md.
- Принимаем риск: квантизация весов на сервере через API не видна, в отчёт попадает имя модели, а не хэш весов.

## Когда пересмотреть

Если на эталоне выигрыша над OCR нет, модель остаётся выключенной. Если чтение по ячейкам слишком долгое для больших комплектов, читаем основную надпись одним запросом. Если документная OCR-модель, например PaddleOCR-VL, не работает через этот API, добавляем ей адаптер за тем же интерфейсом. Если лимит памяти задания снимут, а модель войдёт в образ, вернёмся к варианту B.
