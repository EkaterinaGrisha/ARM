# ADR-0026. Групповая спецификация по варианту А: строка переменных данных несёт своё исполнение

Статус: Предложено · Дата: 2026-11-10 · Этап плана: 4

## Вопрос

Как ядро читает групповую спецификацию по варианту А ГОСТ 2.113, где переменные данные каждого исполнения записаны под его обозначением, и как дерево изделия раскрывает по ней исполнение «-01»? Это пробел «групповые документы» шага 5 [порядка работ](../PLAN.md#порядок-работ-до-демо), оставленный решением [ADR-0025](0025-group-spec-variant-b.md).

## Контекст и ограничения

- Кейс: «Разбор спецификаций и восстановление дерева изделия: сборочные единицы раскрываются рекурсивно по собственным спецификациям»; критерий 2 — «Найдены ли все расхождения, включая неочевидные» (CASE.md, стр. 2 и 3).
- ГОСТ 2.113-75, п. 5.5.1. По варианту А групповую спецификацию выполняют на форме 1 ГОСТ 2.106. Сначала записывают постоянные данные — общие для всех исполнений. Затем идёт заголовок «Переменные данные для исполнений», под ним — обозначение каждого исполнения как заголовок и его составные части по разделам. Позиции исполнений продолжают нумерацию постоянных данных, и у разных исполнений одна позиция может называть разные части.
- [ADR-0025](0025-group-spec-variant-b.md): исполнение без своей спецификации раскрывается по групповой спецификации базы. По варианту Б строке задаётся количество по графам исполнений (`SpecRow.quantities`), номера граф — в `Specification.variants`.
- Правила: сначала контракт; у значения — `Evidence`; слова ГОСТ — в `configs/dictionaries.yaml` ([CONTRIBUTING.md](../../CONTRIBUTING.md#engineering-rules)).
- Факт: ядро не знает заголовков варианта А. Заголовок «Переменные данные для исполнений» и обозначение исполнения стоят в графе «Наименование» и, если длинные, заходят в соседние графы. Строка без позиции и обозначения считалась продолжением наименования строки выше, поэтому заголовки дописывались к нему. Исполнение «-01» искало спецификацию со своим обозначением.
- Факт: на синтетике с OCR это 10 лишних срабатываний из 81: 6 `B1.SPEC.001` у исполнений групповых сборочных единиц и 4 `B1.NAME.001` у строк, к наименованию которых дописан заголовок ([synth-kits.md](../../eval/results/synth-kits.md), прогон до решения).

Сценарии:

1. Изделие называет «Узел» и «Узел-01», групповая спецификация «Узла» выполнена по варианту А. У каждого узла в дереве постоянные строки и строки своего исполнения с их количеством.
2. Исполнение «Узел-02» никто не называет. Его строки не раскрываются, а документы, которые они называют, не считаются документами вне спецификаций: спецификация их перечисляет.
3. Строка спецификации, у которой не прочитано наименование, а позиции нет — например, документ раздела «Документация». Обозначение в графе «Обозначение» — строка, а не заголовок исполнения.

## Варианты

- **A. Количество по исполнениям, как у варианта Б.** Строка переменных данных получает `quantities` с одним номером. Контракт не меняется. Строка без прочитанного количества по правилу ADR-0025 идёт во все исполнения, а у варианта А она принадлежит одному. Документу раздела «Документация» приходится ставить «×», которого на листе нет.
- **B. Исполнение строки в контракте.** У строки переменных данных — `SpecRow.variant`, номер исполнения из заголовка над ней; количество остаётся в `quantity`. Номера исполнений по заголовкам дополняют `Specification.variants`. Дерево даёт исполнению постоянные строки и строки с его номером.

| Критерий | A | B |
| --- | --- | --- |
| Сценарий 1 | да | да |
| Строка без прочитанного количества | уходит во все исполнения | остаётся в своём |
| Отчёт о строке | количество в графе, которой на листе нет | как на листе: «Кол.» и исполнение по заголовку |
| Цена | разбор и дерево | контракт 1.7, разбор, дерево, веб и выгрузка |

## Решение

Вариант B.

- Слова ГОСТ — в `dictionaries.yaml`: `variable_data`, заголовок переменных данных. Строка-заголовок узнаётся по буквам всей строки, а не по графе: длинный заголовок графы режут. На листе, прочитанном OCR, допускается сходство не ниже `section_similarity`, как у заголовков разделов.
- Заголовок исполнения — строка без позиции, весь текст которой — одно обозначение изделия без кода документа. Номер исполнения берётся из обозначения: «-01» → «01», базовое — «–». До заголовка переменных данных обозначение в графе «Обозначение» заголовком не считается (сценарий 3).
- Строки под заголовком исполнения получают его номер в `variant`, разделы под ним начинаются заново. `Specification.variants` дополняется номерами по заголовкам в их порядке.
- Дерево. Исполнение берёт строки без `variant` и строки со своим номером. Базовое исполнение без своей графы берёт строки «–». Обозначения строк других исполнений отмечаются как названные спецификацией (сценарий 2).

Решение не покрывает таблицу исполнений группового чертежа: исполнение детали по-прежнему закрывает групповой чертёж базы с «См. табл.» в графе «Масса».

## Последствия

- Контракт 1.7: `SpecRow.variant` — необязательное поле, отчёты прежних версий валидны. Веб и выгрузка XLSX показывают количество строки переменных данных с номером исполнения: «01: 2». Схема, типы и демо-отчёт обновлены.
- Код: `kdcheck.extract.specification` (`_Rows`, заголовки), `kdcheck.tree.product` (отбор строк исполнения), `kdcheck.report.exports`, веб — `rowQuantity`.
- Тесты: вариант А в текстовом слое — заголовки, разрезанные графами, разделы под исполнением; обозначение без наименования в своей графе остаётся строкой; раскрытие базы и исполнения, документ исполнения, которое никто не называет.
- Синтетика ([synth-kits.md](../../eval/results/synth-kits.md)). Лишних срабатываний от варианта А с OCR 1 вместо 10, с моделью 1 вместо 10: на скане, где OCR прочитал заголовок исполнения с посторонними буквами, исполнение по-прежнему ищет свою спецификацию. Без OCR — 1 вместо 6. Тот же прогон закрывает «БЧ» в графе «Формат» и обозначение из имени файла «обозначение_наименование» — это поправки разбора без отдельного решения. Вместе с ними:

- `arm-1` без модели и с моделью ([arm-kits-dev.md](../../eval/results/arm-kits-dev.md), [arm-kits-dev-vlm.md](../../eval/results/arm-kits-dev-vlm.md)): без изменений. Групповая спецификация `arm-1` выполнена по варианту Б, заголовков варианта А в комплекте нет, а графу «Формат» модель не перечитывает.

## Когда пересмотреть

- Таблица исполнений группового чертежа читается: исполнение детали проверяется по ней.
- В комплектах АРМ встретятся групповые спецификации по вариантам В и Г или базовые документы.
