# ADR-0012. Настройки — в корневом configs/, отчёт хранит хэш настроек и версии движков

Статус: Принято 2026-10-21 · Этап плана: 3 (шаг 7 плана миграции)

## Вопрос

Где лежат пороги, шаблоны форм, словари и лимиты, как ядро и API их находят и проверяют и как отчёт фиксирует настройки и движки, давшие результат?

## Контекст и ограничения

- Кейс: критерий 4 — «Воспроизводимость запуска и устойчивость к некорректным входным данным» (CASE.md, стр. 4).
- Кейс: комплекты приходят «с возможными расхождениями структуры именования файлов и разными версиями оформления» (стр. 3). АРМ консультирует по «правилам оформления конструкторской документации, принятым в АРМ» (стр. 4). Значит, пороги и словари будут меняться без правки кода.
- Правила: «Thresholds, GOST templates, dictionaries and model choices live in `configs/*.yaml`», «model names and versions are written to the report», смена схемы поднимает `schema_version` ([CONTRIBUTING.md](../../CONTRIBUTING.md#engineering-rules)).
- [ADR-0006](0006-job-execution.md): лимиты задания — в `configs/`. [ADR-0010](0010-repo-layout.md): `configs/` — в корне репозитория. [ADR-0011](0011-core-public-api.md): API берёт из ядра только `schemas`, `run`, `render`, `report`. [ADR-0009](0009-report-contract.md): версия 1.1 добавляет `KitInfo.engines`, `SourceRef.engine` и `engine_version`, а ещё `rule_id`, статусы и `extensions`.
- Факт: в ядре вне выгрузок 302 числовых литерала, кроме 0 и 1. Пороги, допуски и геометрия форм — в 10 модулях, больше всего в `extract/title_block.py` и `ingest/document.py`.
- Факт: лимиты API — шесть переменных `ARM_*`, их значения по умолчанию записаны в `backend/arm_web/main.py` и `pipeline/__init__.py`.
- Факт: Docker и быстрый старт из README ставят ядро обычной установкой (`pip install …/packages/kdcheck`), uv в разработке — в режиме editable.
- Факт: PyYAML 6.0.3 (MIT) уже поставляется: его тянет `uvicorn[standard]` (`backend/requirements.txt`).
- Проба: `configs/`, подключённый в пакет символьной ссылкой и `package-data`, попадает в колесо при `pip install` и `uv build` и виден в режиме editable.

## Варианты

Где лежат файлы и как ядро их находит:

- **A. Только корневой `configs/`.** Каталог берётся из `kdcheck run --config`, иначе из `ARM_CONFIG_DIR`, иначе это `configs/` рабочей копии. В образе `ARM_CONFIG_DIR=/app/configs`.
- **B. Корневой `configs/` и его копия в пакете.** Символьная ссылка `kdcheck/configs → configs/` и `package-data` кладут файлы в колесо. Переопределение — как в A.
- **C. Значения по умолчанию в моделях pydantic**, YAML только переопределяет их.

| Критерий | A. Корневой каталог | B. Копия в пакете | C. Умолчания в коде |
| --- | --- | --- | --- |
| Пороги в коде | нет | нет | все: «Готово, когда» шага 7 не выполнено |
| Источник значений | один | один, но установленная копия отстаёт до переустановки | два: код и YAML |
| Ядро, установленное вне рабочей копии | нужна `ARM_CONFIG_DIR` | работает | работает |
| Порог меняется без пересборки образа | том или `ARM_CONFIG_DIR` | то же | то же |
| Особые механизмы | нет | символьная ссылка в git, порядок `COPY` в Dockerfile | нет |

Остальные развилки:

- **Формат.** YAML через `yaml.safe_load` и проверку моделями pydantic с `extra="forbid"`. TOML из стандартной библиотеки противоречит правилу о `configs/*.yaml`.
- **Передача в код.** Ядро загружает настройки один раз за прогон и передаёт разделы стадиям явно. Глобальный объект настроек проще подключить, но он прячет зависимость: стадию нельзя запустить в тесте со своими порогами.
- **Лимиты API.** `configs/api.yaml` читает сам API, переменные `ARM_*` переопределяют значения. В `kdcheck run` API передаёт `--config` своего каталога, поэтому ядро и API читают одни файлы. Если перенести лимиты в настройки ядра, ядро начнёт знать о загрузках и HTTP.
- **Контракт.** Версия 1.1 выходит сейчас и содержит только воспроизводимость: `KitInfo.engines`, `KitInfo.config_sha256`, `SourceRef.engine`, `SourceRef.engine_version`. Остальное из ADR-0009 — `rule_id`, `Extracted.status`, новые статусы документов, `extensions`, `extra="forbid"` — выходит версией 1.2 на шаге 8. Если ждать шага 8, шаг 7 не сможет записать версии движков в отчёт.
- **Хэш.** SHA-256 канонического JSON проверенных настроек после переопределений `--max-pages`, `--no-ocr`, `ARM_OCR`, `ARM_PDF_BACKEND`, `ARM_MAX_PAGES`. Комментарии и разметка YAML хэш не меняют, а порядок записей меняет: часть списков — упорядоченные правила, например первый подошедший вид ТО. `api.yaml` в хэш не входит: на результат он не влияет.

## Решение

Принят вариант A. Порогов в коде не остаётся, источник значений один, особых механизмов нет. Кейс требует прототип и инструкцию по запуску, а не библиотеку для отдельной установки. Ядро запускается из рабочей копии или из образа, и в обоих случаях каталог известен.

Файлы: `forms.yaml` — шаблоны ГОСТ, `ingest.yaml` — чтение файлов и сканов, `dictionaries.yaml` — словари ЕСКД, `criticality.yaml` — критичность Блока 2, `models.yaml` — движки, `api.yaml` — лимиты API. Словари — это перечни терминов: разделы, коды документов, литеры, виды ТО, покрытия, символы допусков. Грамматики обозначений, размеров и шероховатости остаются регулярными выражениями в коде, рядом со своими тестами.

## Последствия

- Модуль `kdcheck.config`: модели настроек, загрузка, хэш. `kdcheck.run` даёт загрузку настроек API и CLI. Если каталога или файла нет или поле неверно, прогон останавливается с именем файла и поля: это сломанная установка, а не плохой файл комплекта.
- `kdcheck run --config DIR`. В Dockerfile — `COPY configs` и `ENV ARM_CONFIG_DIR=/app/configs`.
- Контракт 1.1: `docs/report.schema.json`, типы TypeScript, `docs/report-format.md` и демо-отчёт обновляются.
- import-linter: `arm_web` не импортирует `kdcheck.config` напрямую, список публичных модулей ADR-0011 не меняется.
- Тест-ограничитель: числовые литералы ядра, кроме 0–3, берутся только из списка с причинами, например единицы, повороты PDF, оформление. `report/exports.py` и `schemas` в проверку не входят.
- Значения переносятся как есть: отчёт по демо-комплекту не меняется, кроме новых полей `kit` и источников.
- Генератор `synth/` сохраняет свою геометрию: тестовые данные не зависят от проверяемого кода (ADR-0010).
- README: таблица переменных `ARM_*` становится таблицей переопределений.

## Когда пересмотреть

Если ядро начнут ставить отдельным пакетом, переходим на B. Если разным держателям КД понадобятся разные бланки, вводим профили — подкаталоги `configs/` — и пишем имя профиля в отчёт.
