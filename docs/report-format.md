# Формат отчёта (`report.json`)

Отчёт — контракт между конвейером обработки и веб-интерфейсом. Любая реализация
блоков 1 и 2 (OCR, VLM, LLM, правила), которая пишет `report.json` в этом формате,
отображается в интерфейсе без изменений фронтенда.

* Модели: [`kdcheck.schemas`](../packages/kdcheck/src/kdcheck/schemas/report.py) (Pydantic)
* JSON Schema: [`report.schema.json`](report.schema.json) — генерируется из моделей
* Типы TypeScript: [`frontend/src/api/report.generated.ts`](../frontend/src/api/report.generated.ts) — генерируются из схемы

Схема и типы обновляются одной командой `sh scripts/export_schema.sh`. Тесты падают, если схема отстала от моделей или типы — от схемы.
* Пример: [`frontend/public/demo/report.json`](../frontend/public/demo/report.json)

Версия формата — поле `schema_version` (сейчас `1.3`). Необязательные поля можно
опускать. Неизвестные поля модели отклоняют, чтобы опечатка в имени поля не прошла
незамеченной; свои данные внешний конвейер кладёт в `extensions`. Отчёты прежних версий
остаются валидными: каждая версия добавляла только необязательные поля (таблица ниже).

| С версии | Поле | Содержимое |
|---|---|---|
| 1.1 | `kit.engines` | движки и библиотеки, от которых зависит результат: `[{"name": "pdfium", "version": "156.0.8076.0"}, …]` |
| 1.1 | `kit.config_sha256` | SHA-256 настроек `configs/*.yaml`, с которыми получен отчёт: одинаковый хэш — одинаковые пороги, шаблоны и словари |
| 1.1 | `SourceRef.engine`, `SourceRef.engine_version` | движок, прочитавший текст значения, и его версия: `pdfium`, `tesseract` |
| 1.2 | `discrepancies[].rule_id` | правило, которое нашло расхождение: `B1.NAME.001` (раздел «Правила Блока 1») |
| 1.2 | `Extracted.status` | статус значения: `ok`, `low_confidence`, `missing`, `conflict` (раздел «Прослеживаемость») |
| 1.2 | `documents[].status`: `encrypted`, `duplicate_file` | PDF под паролем и побайтовая копия другого файла (раздел «Статусы документов») |
| 1.2 | `extensions` | данные внешних конвейеров: `{"<имя конвейера>": {…}}`; модели ядра их не разбирают |
| 1.3 | `documents[].pages[].format` | формат листа по ГОСТ 2.301 по размеру страницы: `A4`, `A3`, `A4x3`… (раздел «Страницы») |
| 1.3 | `documents[].pages[].problem` | почему страница не прочитана или не разобрана; остальные страницы файла обработаны |

## Прослеживаемость

Каждое извлечённое значение несёт ссылку на источник `SourceRef`:

```json
{
  "document_id": "d30d4d43f1d",
  "page": 1,
  "bbox": [0.7641, 0.8058, 0.9268, 0.8435],
  "text": "АРМ.303411.000 СБ",
  "method": "text_layer",
  "confidence": 0.95,
  "engine": "pdfium",
  "engine_version": "156.0.8076.0"
}
```

* `bbox` — область `[x0, y0, x1, y1]` в **долях** ширины и высоты страницы, начало
  координат в левом верхнем углу. Так область не зависит от разрешения растра и
  одинаково работает для векторных PDF и сканов.
* `method` — `text_layer` (текстовый слой PDF), `ocr`, `vlm`, `llm`, `filename`
  (из имени файла), `rule`, `manual`.
* `engine`, `engine_version` — чем прочитан текст; у значений из имени файла их нет.

Значение поля — `Extracted`: `{value, raw, confidence, status, source}`, где `raw` — исходный
распознанный текст, `value` — нормализованное значение, `status` — статус значения (с версии 1.2):

| Статус | Смысл |
|---|---|
| `ok` | значение принято |
| `low_confidence` | проверить по документу: прочитано способом из списка `review.methods` или с уверенностью ниже `review.min_confidence` ([`configs/ingest.yaml`](../configs/ingest.yaml); по умолчанию — `ocr`, `filename` и уверенность ниже 0,6) |
| `missing` | значения нет; `source` показывает, где его искали |
| `conflict` | источники дают разные значения; ставит конвейер, который их сравнил, базовый пока не ставит |

Интерфейс подчёркивает значения `low_confidence` и `conflict` как требующие проверки. В отчётах
до версии 1.2 статуса нет, и интерфейс такие значения не отмечает.

## Разделы

| Поле | Содержимое |
|---|---|
| `kit` | идентификатор, название, изделие верхнего уровня, время и длительность обработки, конвейер, движки с версиями, хэш настроек |
| `summary` | счётчики для сводки: документы по статусам и типам, расхождения по типам, укомплектованность |
| `documents` | все файлы комплекта: путь, страницы и их размеры, тип, происхождение (вектор/скан), статус, пояснение |
| `specifications` | разобранные спецификации: поля основной надписи и строки (раздел, формат, зона, поз., обозначение, наименование, кол., примечание) |
| `tree` | дерево изделия: узлы с видом, количеством (в т. ч. на изделие), ссылками на спецификацию и чертежи, статусом и расхождениями |
| `discrepancies` | расхождения блока 1 с правилом, типом, важностью, ожидаемым/фактическим значением, документами и источниками |
| `parts` | данные чертежей блока 2: основная надпись, пункты ТТ, параметры в единой структуре |
| `critical_parameters` | параметры, потенциально критичные для производства, с правилом и обоснованием |
| `quality` | необязательно: метрики по эталону, разбор ошибок, ограничения |
| `log` | замечания конвейера |
| `extensions` | данные внешних конвейеров по имени конвейера |

### Страницы (`documents[].pages`)

| Поле | Содержимое |
|---|---|
| `number` | номер страницы, начиная с 1 |
| `width`, `height`, `unit` | размер страницы: `pt` у PDF, `px` у изображений; 0 — страница не открылась, размер неизвестен |
| `has_text` | у страницы есть текст: текстовый слой или результат OCR |
| `format` | формат листа по ГОСТ 2.301 (с версии 1.3) |
| `problem` | почему страница не прочитана или не разобрана (с версии 1.3) |

### Статусы документов (`documents[].status`)

| Статус | Смысл |
|---|---|
| `ok` | прочитан и разобран |
| `warning` | обработан частично (скан без OCR, не найдена основная надпись…), см. `problem` |
| `damaged` | файл повреждён или пуст |
| `encrypted` | PDF защищён паролем, без пароля не прочитать (с версии 1.2; раньше — `damaged`) |
| `unreadable` | скан низкого качества: распознавание невозможно |
| `foreign` | посторонний документ: нет основной надписи чертежа и граф спецификации |
| `unsupported` | формат не PDF и не изображение |
| `duplicate_file` | побайтовая копия другого файла комплекта, `problem` называет его; копия не разбирается и не даёт расхождения `duplicate_designation` (с версии 1.2) |

### Типы расхождений (`discrepancies[].type`)

| Тип | Когда |
|---|---|
| `missing_drawing` | позиция есть в спецификации (раздел «Детали» или документ из «Документации»), а чертежа в комплекте нет; позиции с примечанием «БЧ» не проверяются |
| `missing_specification` | сборочная единица указана, но её спецификации нет — раскрыть состав невозможно |
| `orphan_drawing` | чертёж есть в комплекте, но не входит ни в одну спецификацию |
| `name_mismatch` | наименование на чертеже (или в собственной спецификации СЕ) отличается от наименования в спецификации; сравнение без учёта регистра, «ё/е» и пунктуации |
| `duplicate_designation` | одно обозначение у нескольких документов (кроме листов многолистового документа) или у разных позиций спецификаций |
| `revision_mismatch` | в комплекте разные версии документа (номер изменения или литера), литеры спецификации и её сборочного чертежа различаются, литера составной части ниже литеры изделия |

### Правила Блока 1 (`discrepancies[].rule_id`)

Каждое расхождение находит одно правило, его код — в `rule_id`, заголовок — в `title`. Логика и тексты правил —
в [`kdcheck.checks`](../packages/kdcheck/src/kdcheck/checks/rules.py), включение и важность — в
[`configs/checks.yaml`](../configs/checks.yaml), ниже — значения по умолчанию. На каждое правило есть тест,
где оно срабатывает, и тест на близкий случай, где оно молчит.

| Правило | Тип | Важность | Когда срабатывает |
|---|---|---|---|
| `B1.MISSING.001` | `missing_drawing` | высокая | у позиции раздела «Детали» нет чертежа в комплекте; позиции с «БЧ» в примечании не проверяются |
| `B1.MISSING.002` | `missing_drawing` | высокая | документа из раздела «Документация», например сборочного чертежа, нет в комплекте |
| `B1.SPEC.001` | `missing_specification` | высокая | у сборочной единицы нет своей спецификации, состав не раскрыть |
| `B1.ORPHAN.001` | `orphan_drawing` | средняя | документ комплекта не указан ни в одной спецификации; сборочный чертёж указанной сборочной единицы в комплект входит |
| `B1.NAME.001` | `name_mismatch` | средняя | наименование на чертеже отличается от спецификации без учёта регистра, «ё/е» и пунктуации |
| `B1.NAME.002` | `name_mismatch` | средняя | собственная спецификация сборочной единицы называет её иначе, чем вышестоящая |
| `B1.DUP.001` | `duplicate_designation` | высокая | одно обозначение у нескольких документов; листы одного документа в разных файлах — не дубликат |
| `B1.DUP.002` | `duplicate_designation` | высокая | одно обозначение у позиций спецификаций с разными наименованиями |
| `B1.DUP.003` | `duplicate_designation` | высокая | одно обозначение у нескольких спецификаций |
| `B1.VERSION.001` | `revision_mismatch` | средняя | документы с одним обозначением различаются номером изменения или литерой |
| `B1.LITERA.001` | `revision_mismatch` | средняя | литеры спецификации и её сборочного чертежа различаются |
| `B1.LITERA.002` | `revision_mismatch` | средняя | литера составной части ниже литеры сборочной единицы (ГОСТ 2.103) |

### Параметры (`parts[].parameters`)

Единая структура для сравнения деталей и загрузки в учётные системы:

| Поле | Пример |
|---|---|
| `category` | `dimension_tolerance`, `general_tolerance`, `roughness`, `geometric`, `heat_treatment`, `hardness`, `coating`, `other` |
| `name` | `Ø50k6`, `Ra 0,8`, `↗ биения`, `Твёрдость HRC`, `Цементация` |
| `value` / `value_min` / `value_max`, `unit` | `0.8 мкм`; `58…62 HRC`; глубина слоя `0,8…1,2 мм` |
| `qualifier` | поле допуска `k6`, шкала `HRC`, базы `А-Б`, код покрытия |
| `it_grade` | квалитет (6 для `k6`, 14 для общих допусков) |
| `general` | общее требование: неуказанные предельные отклонения, шероховатость остального |
| `critical` | отмечен как критичный |
| `text`, `source` | исходный текст и место на странице |

### Правила отбора критичных параметров (`critical_parameters[].rule`)

Пороги — в [`configs/criticality.yaml`](../configs/criticality.yaml), ниже — значения по умолчанию.

| Правило | Критерий |
|---|---|
| `tight_fit` | квалитет IT6 и точнее |
| `fine_roughness` | Ra ≤ 0,8 мкм (Rz ≤ 6,3); отмечается минимальное значение в комплекте |
| `high_hardness` | твёрдость ≥ 45 HRC |
| `chemical_heat_treatment` | цементация, нитроцементация, азотирование |
| `tight_geometric` | допуск формы/расположения ≤ 0,02 мм |
| `rare_in_kit` | покрытие встречается у одной детали комплекта |

Обоснование (`reason`) включает положение значения в распределении по комплекту
(«точнее 69 % посадочных размеров комплекта»), оценка `score` 0–1 задаёт порядок разбора.
