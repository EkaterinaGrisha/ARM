# Сверка прототипа с архитектурой

Дата: 20.10.2026 · Этап плана: 0 · Предмет: прототип из PR #1 — `backend/`, `frontend/`, `samples/`, `docs/report-format.md`, `docs/report.schema.json`.

Прототип сверен с [текстом кейса](../CASE.md), [инженерными правилами проекта](../../CONTRIBUTING.md#engineering-rules) и [целевой архитектурой](../ARCHITECTURE.md). Код в ходе сверки не менялся.

## Итог

Прототип — хорошая основа, переписывать его не нужно. Он находит все пять типов расхождений и извлекает поля Блока 2 на векторных PDF, хотя наименования и номер изменения сверяет не полностью. Источник каждого значения сохранён, битые файлы обработку не роняют. Главные пробелы: ядро не отделено от веб-сервиса, PyMuPDF под AGPL подключён напрямую, пороги зашиты в код, недоверенные файлы разбираются в процессе API без лимитов, тесты зависят от шрифта ОС. Предлагаем развивать прототип по шагам: формат отчёта прототипа взять за основу контракта, Redis и RQ заменить отдельным процессом на задание. Первый шаг — окружение и CI этапа 0 с воспроизводимыми тестами, затем вынос контракта в `kdcheck`.

## 3. Соответствие инженерным правилам

| Правило | Статус | Доказательство |
| --- | --- | --- |
| Ядро отдельно | частично | Логика собрана в `arm_web/pipeline/baseline` за протоколом `Pipeline`, есть CLI. Но ядро лежит внутри пакета веб-сервиса, и API импортирует его внутренности: `main.py:29`, `render.py:11` |
| Сначала контракт | частично | Pydantic-модели, `schema_version`, JSON Schema из моделей. Но `extra="allow"` пропускает опечатки (`models.py:44-45`), типы TS написаны вручную (`frontend/src/api/types.ts:1`), модель задания лежит в модуле контракта (`models.py:285`) |
| Прослеживаемость | частично | У значения есть документ, страница, bbox в долях листа, метод, уверенность (`models.py:48-58`). Нет версии движка и статуса значения, sha256 — только у файла |
| Устойчивость | частично | Ошибка файла или разбора не роняет комплект (`document.py:174-185`, `pipeline.py:65-71`). Нет перехвата по страницам (`document.py:200-216`), лимитов размера, страниц и времени. Зашифрованный PDF попадает в «повреждённые» (`document.py:195`). Разбор идёт в потоках процесса API (`jobs.py:54`) |
| Сначала правила | соблюдено | Текстовый слой, геометрия форм ГОСТ, регулярные выражения; OCR — только для листов без текста (`document.py:203-215`) |
| Настройки вне кода | нарушено | Шаблоны форм (`title_block.py:18-30`), пороги качества скана (`document.py:319-329`), OCR (`ocr.py:42-48`), критичность (`critical.py:46-77`) — в коде. Каталога `configs/` нет |
| Воспроизводимость | частично | Сид генератора закреплён (`demo_kit.py:650`). Версии Python-зависимостей не закреплены (`requirements.txt`: `>=`), версии Tesseract и PyMuPDF не пишутся в отчёт, тесты зависят от шрифта ОС |
| Проверки | частично | Типы расхождений и коды правил критичности есть, сообщения на русском. Нет `rule_id` вида `B1.NAME.001` у расхождений (`models.py:181-192`), отрицательных тестов мало |
| Оценка | частично | Метрики считает `evaluate.py`, но только на синтетике. `eval/gold/` нет — это этап 8 |
| Безопасность данных | соблюдено | Задания лежат в `backend/data/` (в `.gitignore`), обращений к внешним сервисам нет |
| Лицензии | нарушено | PyMuPDF (AGPL-3.0) импортируется напрямую: `document.py:16`, `render.py:8`, `demo_kit.py:20`. Адаптера и решения нет. Остальные зависимости — MIT, BSD, Apache-2.0, ISC |
| Языки | нарушено | Докстроки и комментарии на русском, например `jobs.py:1-9`. Сообщения коммитов уже на английском |

## 8. Риски и открытые вопросы

- Реальных данных нет: все метрики синтетические, основные надписи сканов на демо — 38 %.
- Трактовка расхождения «по литере или номеру последнего изменения» (B1.T5) не согласована с АРМ.
- Способ OCR для сканов выбираем на этапах 5–6 замером: Tesseract на весь лист против сетки надписи и OCR по ячейкам.
- В данных три вида листов: векторные, растровые без сканирования и сканы (стр. 3). Стратификацию эталона в [PLAN.md](../PLAN.md) (этап 8) нужно дополнить растром.
- До шага 5 недоверенные файлы разбираются в процессе API без лимитов, поэтому чужие комплекты на демо-стенде не запускаем.
- Подписи типов и статусов заданы дважды: `backend/arm_web/labels.py` и `frontend/src/lib/labels.ts`.
