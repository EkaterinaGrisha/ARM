Разметка учебных комплектов из реестра [open_drawings.csv](../open_drawings.csv): что лежит в каждом файле и какие расхождения должна найти проверка. Пока нет комплектов АРМ, это единственные реальные данные для Блока 1. Формат — `KitTruth` из [synth/truth.py](../../synth/src/synth/truth.py), как у синтетических комплектов: отчёт с обоими сравнивает один и тот же код.

Сами PDF лежат в `data/open_drawings/` вне git, разметка — здесь. Разметку комплектов АРМ в git не кладём: в ней данные заказчика.

## Порядок

1. Скачать корпус: `uv run python eval/open_drawings.py fetch`.
2. Создать свой черновик: `uv run python eval/gold.py template github/snowlue_ITMO_works --by katya`. Получится `drafts/github/snowlue_ITMO_works.katya.json` — файлы комплекта с пустыми графами.
3. Заполнить черновик по PDF. Отчёт ядра до конца разметки не открывать: эталон не должен подстраиваться под ядро.
4. Проверить формат: `uv run python eval/gold.py check`.
5. Когда комплект разметили двое, сверить черновики: `uv run python eval/gold.py agree`. Итог — `eval/results/gold-agreement.md`.
6. Каждое несовпадение разобрать вместе и записать решение в протокол ниже. Согласованная разметка — `github/<папка>.json`. После этого её не правят: исправление — новая запись в протоколе и новая версия файла.

## Что заполнять

| Где | Что |
| --- | --- |
| `root` | обозначение изделия верхнего уровня: спецификация, которая не входит ни в одну другую |
| спецификация | из основной надписи: `designation`, `name`, `litera`, `revision` — номер последнего изменения, `sheets`; строки — в `rows` |
| строка спецификации | `section` — раздел над строкой; `fmt`, `pos`, `designation`, `name`, `qty`, `note` — как в графах |
| чертёж | `designation`, `name`, `litera`, `revision`, `sheets`; также `material`, `mass`, `scale`, `archive_number`, `first_use` — по ним проверим основную надпись в Блоке 2 |
| схема, перечень элементов, чертёж общего вида | вид `other`: `designation`, `name`, `litera`, `revision`, `sheets` |
| `problem_files` | файл, который не документ комплекта: 3D-вид, титульный лист, технологический документ — статус `foreign` |
| `discrepancies` | расхождения, которые должна найти проверка: `type`, `designation`, `comment` — почему расхождение есть |
| `notes` | спорные случаи комплекта, по строке на случай |

Вид документа (`kind`) шаблон берёт из реестра; если он неверен, его исправляют. Технические требования (`requirements`, `parameters`) пока не размечаем.

## Как переписывать значения

- Как написано в документе. Ошибки автора не исправляем: опечатка автора остаётся в значении.
- Перенос строки внутри графы — один пробел, двойной пробел — один.
- Пустая графа — `""`; графы нет на бланке — `null`.
- Регистр, «ё» и десятичную запятую не меняем: сравнение их не различает.
- Наименование на нескольких строках спецификации — одна строка `rows`, части через пробел.
- `section` — подчёркнутый заголовок над строкой: «Документация», «Сборочные единицы», «Детали», «Стандартные изделия», «Прочие изделия», «Материалы».

## Какие расхождения ставить

Типы и правила — из [каталога](../../docs/report-format.md#правила-блока-1-discrepanciesrule_id). Расхождение ставим, если технолог на входном контроле вернул бы его конструктору. В `designation` — обозначение позиции или документа, к которому оно относится; у позиции без обозначения — `""` и наименование в `name`.

| Тип | Когда | Пример из этих комплектов |
| --- | --- | --- |
| `missing_drawing` | позиции из «Деталей» или документа из «Документации» нет в комплекте; позиции «БЧ» не считаем | ИТМО: у деталей СУИР.06.06.04–08 нет чертежей |
| `orphan_drawing` | документ комплекта не указан ни в одной спецификации | |
| `name_mismatch` | наименование на чертеже отличается от строки спецификации больше, чем регистром, «ё» и пунктуацией | |
| `duplicate_designation` | одно обозначение у разных документов или у позиций с разными наименованиями | ЛЭТИ: ПМИГ 2208.23.001 — «Основание» и «Кожух» |
| `revision_mismatch` | разные литеры или номера изменений у документов одного изделия | |
| `missing_specification` | у сборочной единицы нет своей спецификации | |
| `position_anomaly` | у позиции нет обозначения или количества, позиция повторяется или пропущена; в отчёте такого типа ещё нет | модуль питания: позиции без обозначений |

Остальные типы плана — `format_mismatch`, `sheets_missing`, `section_mismatch`, `first_use_mismatch` — тоже можно ставить: правил для них у ядра пока нет, но эталон их запомнит.

## Двойная разметка

Комплект ЛЭТИ размечают двое независимо: в нём самые спорные случаи. Это 12 файлов из 25, больше 15–20 %, которые требует план. Доля совпадений — в `eval/results/gold-agreement.md`. Её считают по значениям, которые заполнил хотя бы один разметчик, после нормализации.
