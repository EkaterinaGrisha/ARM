# Оценка качества

Замеры, на которые ссылаются документы. Любая цифра о качестве берётся из файла в `results/`. Что считается верным извлечением, задаёт одно правило для всех замеров — [gold/README.md](gold/README.md#что-считается-верным-извлечением); в коде оно записано один раз, в `scoring.py`.

По способу: найдено, лишних, точность, полнота, F1, верная область, время на лист, причины пропусков; у моделей ещё счёт без записей вне строк OCR и расхождения прочтений одной строки | [results/drawing-field.md](results/drawing-field.md) |

Виды — символ-двойник, потерян знак, лишний знак, спецсимвол, подпись графы склеена со значением, захвачен соседний текст, строка прочитана с потерями, неверное значение, значение не прочитано, строка пропущена, пункты склеены, лишние значения и строки, значение достроено моделью, неверная область; по виду входа и классу качества, по полю и движку; изменения символов и двойники; время на лист. `build` собирает корпус в `data/synth/reading` и пишет манифест [reading_corpus.json](reading_corpus.json); `run` сверяет файлы с манифестом, `--vlm` — с моделью, `--stress` — и сканы стрессового корпуса Augraphy, только для замера, `--tag` — метка прогона в именах файлов, `--score` — пересчёт по отчётам прошлого прогона без ядра. Запуск из корня репозитория: `uv run python eval/pdf_backends.py`; PyMuPDF для сравнения ставится с `uv sync --all-packages --all-extras`. Цифры OCR зависят от версии Tesseract, а время — от машины: оба записаны в файл результата. После перегенерации демо-комплекта (`uv run python -m synth.demo_kit samples/demo_kit`) замер повторяют: сканы получаются новыми, и цифры OCR меняются.

`synth_kits.py` собирает корпус по сиду в `data/synth/kits` (вне git) и прогоняет ядро с OCR и без; комплекты, разметка и цифры повторяются на любой машине с тем же Tesseract. `scan_quality.py` так же собирает свой корпус в `data/synth/scan_kits`, а реальные сканы берёт из `data/gold_sheets` (`eval/gold.py sheets`).

Стрессовый корпус — те же комплекты, что у `scan_quality.py`, со сканами через конвейер Augraphy по умолчанию — собирается один раз на версию генератора и замораживается манифестом [stress_corpus.json](stress_corpus.json); когда генератор меняет документы комплектов, корпус пересобирают, иначе его чертежи не совпадут с чертежами своего модуля. В манифесте — sha256 всех файлов, версии Python и библиотек, сиды, настройки и эффекты каждого листа. Файлы — в `data/synth/stress` (вне git). Augraphy работает только на Python 3.11 и ставится отдельной группой: `uv run --group augraphy python -m synth.stress build data/synth/stress`. На той же платформе с теми же версиями сборка повторяет файлы байт в байт. `uv run python -m synth.stress verify data/synth/stress` сверяет файлы без Augraphy; `scan_quality.py` сверяет их сам перед замером, а без корпуса пропускает его строки.

Отложенный корпус — комплекты `synth.kits` с теми же долями сканов, растров и комплектов по листу в файле, что у `synth_kits.py`, но со своим сидом и числом комплектов, при котором на каждый обязательный тип кейса заложено не меньше 30 расхождений. На корпусе сида 1 настраиваются правила, поэтому его цифры — цифры настройки; отложенный корпус меряется один раз, после заморозки правил, вместе с `arm-2` и `arm-3`. Он собирается из закоммиченного генератора и замораживается манифестом [heldout_corpus.json](heldout_corpus.json): sha256 всех файлов, параметры, коммит и sha256 генератора, версии библиотек и сколько расхождений каждого типа и правила заложено. Файлы — в `data/synth/heldout` (вне git). `uv run python -m synth.heldout build data/synth/heldout` собирает корпус в пустую папку, `uv run python -m synth.heldout verify data/synth/heldout` сверяет файлы с манифестом.

Демо-комплект синтетический, чертежей-сканов в нём два. Поэтому эти замеры показывают, что ничего не сломалось, но не дают оценку качества. Её даст эталонная выборка (этап 8 плана).
